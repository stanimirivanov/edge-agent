# Atomic research completion

## TL;DR

- Prepare the terminal outcome before opening a transaction; recover receipts first.
- Commit request completion, inbox delivery and exact outbox intent together.
- Same scoped request returns the original result; changed request bytes conflict.
- Run `cargo xtask verify --check research-persistence --python python3` with an explicitly selected loopback `EDGEAGENT_POSTGRES_URL`.

## Boundaries and message bindings

[`publication`](../../crates/research-application/src/publication.rs) defines the
persistence-neutral port, validated preparation/receipt types and local routing
contracts. The Research-owned evaluation command carries the existing v1 Request
record. Gateway or MarketData must be authenticated by the future outer adapter;
source URI checks alone do not authenticate them. Partition and subject are
`research-request/<caller-scope>/<request-id>`; idempotency is the exact request
record digest. An artifact or abstention event carries the canonical terminal
record, produced by Research, with ID equal to the terminal content digest.
Correlation/trace context and first causation are retained. Occurrence time is an
explicit input, not generated by the transaction. No worker or topology is activated.

Call `recover` with the original evaluation delivery before evidence reads or
rendering. `None` does not mark the inbox or claim completion. A retained result
validates exact request content, canonical terminal/event bytes, partition/source/
event identity and matching outbox intent. It records a new delivery identity in
the same transaction when needed. Recovery does not reauthorize evidence use or
retrieve stored market-data objects. The port returns a receipt only after commit;
the public receipt decoder alone proves neither commit nor owner authority.

## Transaction and idempotency

[`research-postgres`](../../crates/research-postgres/src/lib.rs) owns a single
terminal table keyed by caller scope and request ID. Row existence is request
completion; it is not gateway admission or a pending-job queue. Every record is
terminal and immutable. The request, outcome and publication bytes are stored in
one row, with inbox recording and the existing outbox enqueue in one transaction.
All calculation, evidence reads and authorization occur before this transaction.

Use a pool scoped to Research's private schema and runtime role. The adapter sets
READ COMMITTED isolation, a five-second lock timeout and fifteen-second statement
timeout. An overall operation deadline/cancellation remains the caller's obligation.
Competing inserts serialize on the scoped key; a subsequent statement sees the
winner. Exact request reuse returns the first retained outcome even if a newly
rendered candidate differs. Changed request content conflicts and rolls back the
new inbox write. Duplicate inbox without completion and pre-existing orphan outbox
intent fail closed. ACK the broker only after successful commit/recovery.

Storage failure at commit can be ambiguous: retry/recover the same identity, never
invent another request, delete state or republish a newly rendered result.
SQL errors retain typed causes while normal Debug/Display omit driver/payload data.

## Migration, permissions and rollback

Apply existing inbox/outbox migrations and the
[research migration](../../crates/research-postgres/migrations/0001_research_completions.sql)
in a new Research-owned schema before enabling a future consumer. Do not apply
it to a peer's private tables. An update/delete trigger protects immutable terminal
rows. The runtime role needs SELECT/INSERT on completions and required inbox/outbox
permissions; it must not receive DDL, trigger-disable or TRUNCATE privileges.

The retained outbox row is integrity evidence: keep it for the full completion
retention lifetime. Do not independently prune it. Coordinated retention/archival
is future reviewed work. No cleanup scheduler or lifecycle mutation is introduced.
Rollback stops new consumer intake and preserves completion/inbox/outbox rows for
a compatible reader; never drop tables to revert code. No existing data migration,
cluster operation or service activation occurs in this slice.

## Verification and SQLx metadata

The default gate compiles and discovers the five protected ignored database proofs.
The `research-persistence` gate executes real duplicate/conflicting requests,
concurrent completion/client restart, statement/deferred-commit rollback,
cancellation behind an observed transaction barrier, immutability and corrupted
retained outbox refusal. Each proof creates and drops only its own unique schema.
It rejects non-loopback database endpoints and performs no broker publication.
The existing CI `local-platform` job includes the new suite automatically.

`cargo xtask verify --check sqlx-metadata --python python3` now includes Research
migration assembly in the canonical isolated Compose/SQLx workflow. Checked query
metadata is committed under `.sqlx`. When Compose/SQLx CLI is unavailable, report
that gate as not run. Equivalent live macro compilation against a fresh disposable
schema can verify/generate the Research queries, using `SQLX_OFFLINE=false`, an
explicit `DATABASE_URL`, and `SQLX_OFFLINE_DIR` pointing to the workspace `.sqlx`.
This evidence does not claim the full Compose regeneration workflow ran.
